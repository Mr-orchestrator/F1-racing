WHY THIS MATTERS

Without the consent queue, alloy('sendEvent') fires on Library Loaded before the CMP resolves — typically 200–800ms before. Data lands in AEP without a consent signal. Under GDPR Article 7, unconsented data in AEP cannot be used for profiling and is difficult to delete at profile granularity. The bridge queues events and flushes only after alloy('setConsent') succeeds.

SHARED-DEVICE IDENTITY COLLAPSE RISK

If two users share a device and both authenticate, the private identity graph merges their ECIDs under both crmIds. The merge policy (timestamp-ordered) picks the most recent authenticated event's attributes — older profile data is suppressed. Audiences derived from pre-merge events may shrink or switch member without a new qualifying event. The fix is to call alloy('setConsent', {general:'out'}) on logout to break the ECID association before the next user logs in.

AJO IMPRESSION TRACKING — PROPOSITION DISPLAY BUG

After alloy('sendEvent', {renderDecisions: true}) resolves, result.propositions must be acknowledged with a separate decisioning.propositionDisplay event. Without it: AJO journey step "Message displayed" stays at 0, frequency caps never decrement, and the "Interacted" vs "Displayed" ratio is incalculable. 

// WRONG — common in Adobe community threads:
alloy('sendEvent', { renderDecisions: true, xdm: pageViewXdm });
// impression never reported → AJO journey blind

// CORRECT (wired in lib/adobe-websdk-bridge.js AJOTracker):
alloy('sendEvent', { renderDecisions: true, xdm: pageViewXdm })
  .then(function(result) {
    window.__adobeBridge.ajo.notifyDisplay(result.propositions);
  });

AppMeasurement s.t() and alloy sendEvent both fire on the confirmation page during Phase B. AA's server-side purchaseID dedup window (3 min) only works when both hits carry the same RSID — which they do because the Web SDK datastream routes to the same RSID. The result: revenue is doubled in AA Workspace during the overlap window.

P0 Raw email PII sent to Edge (identityMap) FIXED

The original XDM data element set identityMap.Email[0].id = attrs.user_email — plaintext. Adobe's Edge Network rejects raw email with HTTP 400 when DULE I1 enforcement is enabled on the schema. Even without enforcement, raw PII in AEP violates data governance policies and the I1/I2 label contract.

Fix locationdocs/analytics/xdm-data-element-FINAL.js — login/signup blocks
lib/adobe-websdk-bridge.js → IdentityHelper.hashEmail()
MechanismSubtleCrypto SHA-256 async hash. Login XDM fires immediately with crmId; hashed email follows in a separate sendEvent once the Promise resolves. Never falls back to raw email — omits email identity if SubtleCrypto unavailable.
NamespaceChanged from Email (raw) → Email_LC_SHA256 (hashed) per AEP standard namespace.
P0 Consent race: alloy fires before CMP resolves FIXED

Tags Library Loaded rule calls alloy('sendEvent') for the page view on DOM ready. The CookieConsent CMP resolves 200–800ms later (async). Data is sent to AEP with no consent signal. Under GDPR, unconsented data in AEP is difficult to delete at profile granularity and cannot be used for activation.

Wires to window.ccOnConsent callback from cookieconsent-init.js
MechanismConsentQueue.sendEvent() replaces direct alloy() calls. Queue is flushed only after alloy('setConsent') resolves. If denied, queue is discarded and consent:out is sent.
Tags changeLibrary Loaded rule: replace alloy('sendEvent', xdm) with window.__adobeBridge.consent.sendEvent({xdm: xdm})
P1 productListItems built from item_0_* flat pattern (multi-item carts truncated) FIXED

The XDM data element looped over attrs.item_0_id … item_N_id from the triggering push event. This is only populated if each item was explicitly flattened into the event attributes — cart items added in previous events are absent. Result: multi-item checkout/purchase XDM productListItems[] is incomplete. AA product string is short. CJA revenue per product is understated.

P1 ECID not stitched to crmId — pre-auth journey detached in RTCDP FIXED

The login XDM set only identityMap.Email. The private identity graph requires crmId and the device's ECID to appear in the same event to merge the anonymous pre-auth session to the authenticated profile. Without this, the cart abandonment audience misses users who browsed anonymously then authenticated at checkout — the most valuable segment.
